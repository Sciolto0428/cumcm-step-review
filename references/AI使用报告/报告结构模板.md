# AI 使用详情报告：结构模板与逐表填法

## 0. 报告与论文的固定关系

- 论文：在「参考文献」之前放「AI 工具使用声明」，使用版文案必须与报告"是否使用"一致。
- 报告：独立 DOCX/PDF，文件名严格为 `AI工具使用详情.pdf`，放入支撑材料，并在论文附录支撑材料清单中列出。
- 报告只整理**本次解题过程**。用于正式竞赛时，时间必须落在该届竞赛起止时间内且与 `ai_usage_log.md` 一致。

## 1. AI 使用过程留痕（`PROJECT_ROOT/ai_usage_log.md` 的推荐格式）

每冻结一个论文部分，追加一行到该表（同一环节多次使用可拆成多行）：

| 编号 | 论文部分/环节 | 日期时间 | 工具（名称+版本） | AI 参与内容摘要 | 提示词摘要 | 参赛队处置（采纳/修改/弃用/重跑） | 对应文件与论文位置 | 核验 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| S1 | 问题重述 | 竞赛第一天 … | … | 起草问题背景改写与子问题清单 | 请按题意概括背景并拆分子问题 | 部分采纳，人工核对题面后定稿 | `论文草稿.docx` 第 1 部分 | 用户审核通过 |
| S2 | 数据预处理 | … | … | 缺失/异常口径方案、清洗脚本 | 给出清洗口径并实现 | 选定口径、审查代码后运行 | `preprocess.py`、清洗摘要.csv | 前后数据量复核 |
| Q1 | 问题一建模与求解 | … | … | 候选算法比较、公式草稿、求解代码、图 | 给出候选模型及理由 | 选定模型，重写部分公式后运行 | `q1_model.py`、`q1_result.json` | 用户审核 + 结果复核 |
| … | … | … | … | … | … | … | … | … |

留痕原则：每个部分冻结时立即记，不在提交前凭印象补；提示词写"摘要"不写原始全文；工具名/版本/时间为真实值。

## 2. 环节 ↔ Skill 论文部分映射（分环节表默认口径）

| 报告环节（可按当届示例调整） | 对应本 Skill 部分 | 推荐"是否使用"表述 |
| --- | --- | --- |
| 问题理解与题意拆解 | 第 1 部分问题重述、第 8 部分问题分析 | 辅助（AI 出初稿/候选解释，参赛队主导确定） |
| 文献检索与资料整理 | 第 6 部分参考文献 | 使用（真实文献必须人工核验） |
| 模型假设与符号定义 | 第 9、10 部分 | 辅助（AI 出候选，参赛队审定） |
| 模型建立与求解分析 | 第 3 部分各问建模与求解 | 辅助（AI 给候选方案/公式草稿，参赛队选定并定稿） |
| 编程实现与调试 | 各问与预处理代码 | 使用（AI 实现代码，参赛队审查重跑） |
| 数据处理与清洗 | 第 2 部分 | 使用（口径由参赛队定，AI 辅助实现） |
| 绘图与可视化样式 | 各问图表、流程图 | 使用（样式规则与成图由 AI 按参赛队绘图指南实现，参赛队逐图审核） |
| 文字润色/翻译/摘要 | 第 11 部分摘要与全文 | 使用（仅语言组织，不改变数值与结论） |
| 数模智能体/其他 | 全流程智能体工作流 | 使用（详见工具清单与提示方式） |

> 注意：上述"是否使用"落到报告时，凡核心建模相关环节必须同时出现"参赛队主导 + 逐项审核"的处置与核验说明，不能只写"AI 生成"。

## 3. 三档使用程度（先向用户确认档位再填）

| 档位 | 典型范围 | 报告中"是否使用/综述"写法 |
| --- | --- | --- |
| 轻度 | 仅语言润色、代码调试 | 声明用途写"语言润色、代码调试等" |
| 中度 | 润色 + 数据处理/绘图/文献整理等辅助环节 | 核心建模与问题分析未使用 AI 时用此档；写清哪些辅助环节使用 |
| 深度/全程辅助 | AI 参与数据处理、候选建模、代码、图表、文字起草，但参赛队逐项审核定稿 | 声明用途写"数据分析、方案讨论、代码实现与文字组织等辅助工作"；综述强调参赛队主导核心建模并逐项审查 |

本 Skill 默认按"深度/全程辅助 + 参赛队主导定稿"口径执行；用户明确要求更低调档时，先核对该档与留痕是否矛盾（例如留痕有建模候选记录就不能声称"模型建立未使用 AI"），矛盾时须先回查留痕再确定档位。

## 4. 报告 DOCX 结构模板

以下结构与版式可参考通用"中度版"示例；用 `tools/docx/SKILL.md` 的 `paper_format.py` 构建。除特殊说明外均为三线表。

### 标题页/首行

`全国大学生数学建模竞赛`（居中）／`AI 工具使用详情`（居中）

### 一、论文中的「AI 工具使用声明」

两列表：勾选栏 + 声明原文栏。勾选"使用了 AI 工具"，原文照抄官方文案，并把【简要用途】替换为已确认的用途概括。禁止改动固定文案的其余文字。

### 二、所用 AI 工具清单

列：序号 | 工具名称 | 版本或型号 | 提供方/入口 | 一句话用途。所有条目必须与用户确认值一致，不得自行补工具。

### 第一部分　使用概述

1.1 是否使用（与声明一致）：一行表或文字。

1.2 使用环节总表：列 = 环节 | 是否使用 | 工具（名称+版本） | 目的（一句话） | 论文/代码对应位置。按第 2 节映射填全部环节；未使用环节写"未使用"。

1.3 使用情况综述（一段）：写"工具主要承担哪些辅助工作 + 参赛队做了什么（决策、审核、重跑、定稿）+ 核心建模与问题分析由参赛队主导"。禁止出现与下面分环节记录矛盾的概括。

### 第二部分　分环节使用记录

每一环节一个六行表：

| 条目 | 填写内容 |
| --- | --- |
| 是否使用 / 时间 | 使用　<真实日期与时间段>（未使用写"未使用 —"） |
| 工具及版本 | 与工具清单一致 |
| 提示词摘要 | 一句概括，脱敏 |
| AI 输出与处置 | AI 给了什么、参赛队采纳/修改/弃用/重跑，核心内容如何定稿 |
| 核验与对应位置 | 核验方式 + 论文/代码/文件位置 |

必须覆盖环节（可合并）：
2.1 问题理解 / 2.2 模型假设与符号 / 2.3 模型建立与求解分析 / 2.4 编程实现与调试 / 2.5 文字润色、翻译、摘要 / 2.6 其他（文献、数据、绘图、智能体）及未使用汇总。

### 第三部分　提示词与关键对话摘录

说明框：提示词均做脱敏概括处理，不含账号/密钥/内网地址/未公开数据；原始聊天记录由参赛队留存备查。

3.1 主要提示方式表：列 = 方式 | 是否使用 | 说明（一句话），示例行为：网页对话框复制赛题、代码编辑器内联补全/对话、上传文件或粘贴报错日志、智能体/工作流、其他。

3.2–3.3 典型交互示例：每个示例单元格包含：对应环节 / 工具及版本 / 时间 / 本队提示（概括）/ AI 回复摘要 / 本队随后做了什么（采纳/修改/弃用与核验人）。只摘 2–3 个与核心流程相关的真实交互。

### 第四部分　人工贡献与核验

4.1 队员独立完成事项表：列 = 事项 | 是否本队独立完成（是/否 + 说明）。事项至少包括：赛题阅读与问题拆解、模型假设与符号、模型结构与创新点、推导与求解步骤、程序逻辑与参数、数据来源与预处理、结果分析与论文论述及图表。参照留痕如实填写；AI 有参与的实现/预处理/绘图/写作项写"否（AI 辅助，参赛队审查定稿）"。

4.2 人工贡献综述：从赛题阅读到成稿均由参赛队主导；每一条具体说明参赛队做了什么审核动作；AI 输出逐项经人工审查与核实；核心建模与分析由参赛队主导。语言平实、可被留痕佐证。

## 5. 生成与校验命令参考

```powershell
# 一致性审计（必跑，FAIL 即未通过）
python "<SKILL_ROOT>/references/AI使用报告/scripts/ai_report_audit.py" "<PROJECT_ROOT>" --report "<PROJECT_ROOT>/AI使用报告.docx"

# DOCX 结构校验
python "<SKILL_ROOT>/tools/docx/scripts/office/validate.py" "<PROJECT_ROOT>/AI使用报告.docx"

# 导出 PDF 并目测（文件名固定）
python "<SKILL_ROOT>/tools/docx/scripts/office/soffice.py" --headless --convert-to pdf --outdir "<PROJECT_ROOT>" "<PROJECT_ROOT>/AI使用报告.docx"
```

PDF 导出后重命名为 `AI工具使用详情.pdf`（导出与改名时确认无同名旧文件被误覆盖），逐页目测表格、字体、分页与隐私信息。
